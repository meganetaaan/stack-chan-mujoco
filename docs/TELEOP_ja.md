# MuJoCoでWASD操作

リポジトリのルートで、既存のMuJoCo用Python環境から起動する。

```sh
python teleop_yaw.py
```

この作業環境では次のコマンドを使える。

```sh
/home/sskw/stackchan-mujoco/.venv/bin/python teleop_yaw.py
```

ウィンドウをクリックしてフォーカスを合わせる。起動直後はシミュレーション時間で2秒間立位を保ち、その後操作を受け付ける。

| 操作 | 動作 |
|---|---|
| Wを押す | 前進、指令0.10 m/s |
| Sを押す | 後退、指令0.05 m/s |
| A / Dを押す | 左 / 右のその場旋回、指令9度/s |
| キーを離す / Space | 停止指令 |
| R | 初期姿勢へリセット |
| Esc / ウィンドウを閉じる | 終了 |
| 左ドラッグ / ホイール | 視点回転 / ズーム |

押している間だけ指令を継続する。ウィンドウがフォーカスを失っても停止指令に戻る。複数方向は前後を優先し、同じ軸の逆方向同時押しは相殺する。斜め移動は実装していない。足が空中にある間は現在の歩を完了してから指令を切り替え、停止時も足を揃えるため、キーを離した瞬間に姿勢を固定する動作ではない。

r8の浮遊ベースモデルと、正式評価で採用した歩行パラメータを使い、その場で関節参照と静的補償を計算する。物理刻み1 ms、指令20 ms、駆動のトルク・速度・遅延・フィルタ・飽和保護を維持する。転倒・衝突・関節制限・保護異常時は画面に原因を表示し、物理計算を停止する。Rで再開する。CPU性能により実時間より遅くなる場合があるが、物理刻みを飛ばして追いつかせない。

数値参照に必要な生成済みソース・設定は `design/teleop_reference/` に同梱しており、CAD再生成は不要。物理モデルは `assets/r8_yaw_offset_flange_v1/` を使用する。GLFWと表示可能なOpenGLデスクトップが必要（WSLではWSLg等）。正式試験の参照や判定ファイルは変更していない。任意のキー操作列の成功を正式40試行の成績で保証するものではない。

表示なしの24秒切替テスト：

```sh
python teleop_yaw.py --headless
python -m unittest tests.test_teleop_yaw -v
```

## 実時間に近づける設定

WSLでCPU描画のllvmpipeになっている場合、この環境ではD3D12を指定するとAMD RadeonによるGPU描画を使用できる。

```sh
GALLIUM_DRIVER=d3d12 /home/sskw/stackchan-mujoco/.venv/bin/python teleop_yaw.py --fps 15
```

垂直同期の待ち時間をなくし、描画は既定で最大30 fps（`--fps`で変更）、指令処理は50 Hz、物理計算と保護判定は1,000 Hzとして分離した。画面の `Speed` はシミュレーション時間÷実時間で、1.00xが実時間。毎フレームの相対sleepではなく期限を基準に待つ。処理が追いつかなくても物理刻みは飛ばさない。

また、直前の `mj_forward` が計算した位置・速度依存の結果を次の `mj_step2` で再利用する。対応するimplicitfast積分器のみ許可する。位置・速度チェック、更新後の全物理判定、保護判定を維持した。元のmj_step版との24秒切替比較で位置差0、速度は絶対許容1e-12以内、異常判定一致。4秒の回帰テストでは位置・速度の配列が完全一致した。正式評価用エンジン・凍結モデルは変更していない。

この環境の10秒自動操作測定では、30 fpsで11.40秒、15 fpsで10.87秒（約0.92x）。実時間を保証する値ではなく、PC負荷や指令に依存する。変更はアプリを再起動すると適用される。

```sh
GALLIUM_DRIVER=d3d12 python teleop_yaw.py --demo --duration 10 --fps 15
```

終了時にシミュレーション時間・実時間・速度比・異常をJSONで表示する。`--demo` はWASDの代わりに自動指令を使う計測用オプション。
