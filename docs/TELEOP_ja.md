# MuJoCoでWASD操作

リポジトリのルートで、既存のMuJoCo用Python環境から起動する。

```sh
python teleop_yaw.py
```

この作業環境では次のコマンドを使える。

```sh
/home/sskw/stackchan-mujoco/.venv/bin/python teleop_yaw.py
```

ウィンドウをクリックしてフォーカスを合わせる。起動直後はシミュレーション時間で2秒間立位を保ち、その後操作を受け付ける。

| 操作 | 動作 |
|---|---|
| Wを押す | 前進、要求0.025 m/s |
| Sを押す | 後退、要求0.012 m/s |
| A / Dを押す | 左 / 右のその場旋回、要求32度/s |
| キーを離す / Space | 停止指令 |
| R | 初期姿勢へリセット |
| Esc / ウィンドウを閉じる | 終了 |
| 左ドラッグ / ホイール | 視点回転 / ズーム |

押している間だけ指令を継続する。ウィンドウがフォーカスを失っても停止指令に戻る。r9ではW/SとA/Dを同時入力でき、前進・後退しながら左右旋回できる。同じ軸の逆方向同時押しは相殺する。横移動は実装していない。並進中の旋回目標は±12度/sへ制限する。画面には要求・目標・周期平均の実測速度を表示する。[速度追従の仕様・評価手順](VELOCITY_CONTROL_ja.md)を参照。足が空中にある間は現在の歩を完了してから指令を切り替え、停止時も足を揃えるため、キーを離した瞬間に姿勢を固定する動作ではない。

既定はr9の浮遊ベースモデルと高速旋回参照。旋回は0.4秒/歩、荷重移動45%、COM内寄せ25.5 mm、IKヨー範囲±0.245 radを使い、その場で関節参照と静的補償を計算する。停止後の旋回開始時には、方向に合わせて最初の支持脚を選ぶ。前後進はr9の可動範囲と物理試験に合わせて指令値を抑えており、前進0.10 m/sはこのデモでは未達。物理刻み1 ms、指令20 ms、駆動のトルク・速度・遅延・フィルタ・飽和保護を維持する。転倒・衝突・関節制限・保護異常時は画面に原因を表示し、物理計算を停止する。Rで再開する。CPU性能により実時間より遅くなる場合があるが、物理刻みを飛ばして追いつかせない。

数値参照に必要な生成済みソース・設定は `assets/r9_fast_turn_v1/reference/` に同梱しており、CAD再生成は不要。物理モデルは `assets/r9_fast_turn_v1/` を使用する。GLFWと表示可能なOpenGLデスクトップが必要（WSLではWSLg等）。正式試験の参照や判定ファイルは変更していない。任意のキー操作列の成功を正式40試行の成績で保証するものではない。

この操作モードはキーを押している間の連続旋回。90度で自動停止する有限角度試験とは停止条件が異なるため、手動操作で「90度・6歩・2.76秒」を保証するものではない。有限角度試験の再現は [FAST_TURN_RUN_ja.md](FAST_TURN_RUN_ja.md) を参照。

旧r8は `python teleop_yaw.py --profile r8` で起動できる（前進0.10 m/s、後退0.05 m/s、旋回9度/s）。画面とタイトルにプロファイル名を表示する。`--design` / `--cad-design` は選択したプロファイルに対応するモデル・参照ソースを指定する。

表示なしの24秒切替テストと回帰テスト：

```sh
python teleop_yaw.py --headless
python -m unittest tests.test_velocity_control tests.test_teleop_yaw tests.test_teleop_r9 -v
```

## 実時間に近づける設定

WSLでCPU描画のllvmpipeになっている場合、この環境ではD3D12を指定するとAMD RadeonによるGPU描画を使用できる。

```sh
GALLIUM_DRIVER=d3d12 /home/sskw/stackchan-mujoco/.venv/bin/python teleop_yaw.py --fps 15
```

垂直同期の待ち時間をなくし、描画は既定で最大30 fps（`--fps`で変更）、指令処理は50 Hz、物理計算と保護判定は1,000 Hzとして分離した。画面の `Speed` はシミュレーション時間÷実時間で、1.00xが実時間。毎フレームの相対sleepではなく期限を基準に待つ。処理が追いつかなくても物理刻みは飛ばさない。

また、直前の `mj_forward` が計算した位置・速度依存の結果を次の `mj_step2` で再利用する。対応するimplicitfast積分器のみ許可する。位置・速度チェック、更新後の全物理判定、保護判定を維持した。元のmj_step版との24秒切替比較で位置差0、速度は絶対許容1e-12以内、異常判定一致。4秒の回帰テストでは位置・速度の配列が完全一致した。正式評価用エンジン・凍結モデルは変更していない。

旧r8でのこの環境の10秒自動操作測定では、30 fpsで11.40秒、15 fpsで10.87秒（約0.92x）。実時間を保証する値ではなく、PC負荷や指令に依存する。変更はアプリを再起動すると適用される。

```sh
GALLIUM_DRIVER=d3d12 python teleop_yaw.py --demo --duration 10 --fps 15
```

終了時にシミュレーション時間・実時間・速度比・異常をJSONで表示する。`--demo` はWASDの代わりに自動指令を使う計測用オプション。

## Shift＋WASD：向きを保った並進（r9）

左右どちらのShiftでもよい。Shift＋A/Dは左右の横歩き、Shift＋W/Sは向きを保つ前後移動になる。Shift＋W＋Aなどで斜めにも並進できる。Shiftを離すと通常のWASD（A/Dは旋回）に戻る。切り替え時も進行中のステップは完了させる。

| 操作 | 速度要求 |
|---|---|
| Shift＋W / S | 前進0.015 / 後退0.008 m/s |
| Shift＋A / D | 左 / 右へ0.004 m/s |
| Shift＋前後＋左右 | 上記2成分を同時指定 |

Shift操作を始めたときの機体の向きを保持する。横方向の周期平均速度をフィードバックし、踏み出す足から横へ移動する。停止時はその場で両足支持へ戻す。横歩きは低速の初期設定で、実機では未検証。通常操作と同じく、キーを離す・Space・フォーカス喪失で停止、Rで初期姿勢へ戻る。

画面の `Side Req/Tgt/Meas` は横方向の要求・制限後目標・実測速度（m/s）。向きを保つための小さな旋回補正が表示されることがある。瞬間的なヨー角や横速度を完全に固定する動作ではない。

```sh
python -m unittest tests.test_crab_control tests.test_velocity_control tests.test_teleop_yaw tests.test_teleop_r9 -v
python run_crab_evaluation.py --out outputs/crab_evaluation_new --workers 3
```

この評価は名目条件の前後左右・斜め8方向、30秒の横歩き、旋回モードとの切り替えを含む。速度・姿勢の50 Hz記録、合否、ソースハッシュを保存する。初期の合格基準は向きの誤差5度未満、定常時の前後・左右速度誤差0.003 m/s未満、停止後の並進速度0.004 m/s未満・ヨー角速度3度/s未満、立位への復帰、物理・駆動異常なし。重量・摩擦の変動まで含む横歩き評価ではない。

旋回が残っている状態でShiftへ切り替えた場合は、画面に `Stopping turn before translation` と表示し、いったん停止してから並進へ移る。この場合の保持方向は、旋回が止まって並進を開始する時点の向きになる。Shiftを離すと待機を取り消し、通常操作に戻る。

評価結果は `validation/crab_translation_v1/` に保存。10/10条件が通過し、向きの誤差は最大0.575度未満。既存回帰を含む16テストも通過。通常の速度制御の1条件は、保存済みの速度・姿勢記録との配列一致を確認した。
