# E0-D / E1-D：独立サーボバスの放電と逆給電

対象は `schematics/power/servo_power_pololu_discharge_candidate_v1` の候補。現状は試験開始不可。#24でゲートRC、過電圧/回生処理、短絡保護、配線/熱、通信インターフェースの非給電時定格を確定してから#49で実施する。本書は実施結果ではない。

## 目的と判定基準の出所

停止後のサーボ側電圧と、その電圧を維持する流入経路を確認する。0.92秒後0.5V以下は既存の工学的仮基準を維持し、機械停止や無トルクの保証とは分ける。試験結果を見て下限/期限を変更しない。電流注入上限・温度上限・観測時間・測定器設定は実部品定格と完成回路から事前に確定し、空欄なら未実施扱い。

## 最小構成と順序

1. 無通電で左右V+の分離、360Ω2本/脚の実装、逆流FET下流への接続、GND帰路を確認。抵抗1本開放の故障は電源を切り容量の放電を確認してから作る。各抵抗を別々に開放し、位置依存の配線断も確認する。
2. E0-D：実電池とサーボを外し、電流制限可能な電源、独立遮断、既知の容量負荷を使用する。容量・漏れ・ESRの実測/公差と配線を記録。実機容量を960µFと決めつけない。
3. E0-Dで計測系と放電経路を確認後にE1-D：固定した単関節に進み、サーボ内の非線形負荷、通信からの流入、停止時の回生を測る。単関節合格を6軸/脚の合成容量・回生へ外挿しない。
4. 左右それぞれ正常2本、各1本開放を実施。両開放は放電喪失を検出する対照試験で、放電合格を要求しない。抵抗短絡や機械回生の故障注入は別のエネルギー制限条件が成立するまで実施しない。

## 電源状態マトリクス

`power_states.csv` の16状態を左右それぞれで評価する。駆動入力は「存在・給電許可」「存在・停止」「物理切離し」「入力0Vに保持」を分ける。最後の2状態は等価でない。実験電源の逆流吸収能力を確認せず0Vへ設定しない。

各駆動状態に、制御ロジック電源ON/OFF、通信ホスト/変換器電源ON/OFFの4組を組み合わせる。Tab5、USB、変換器など別電源が残る実構成を配線図へ記録する。OFFは信号線を抜く意味ではない。部分給電時の端子定格が満たせない状態は通電せず「設計不適合」と記録する。ケースを黙って省略しない。

通信はまず切離し状態を基準とし、接続後のアイドルと通信中を比較する。トランシーバ未選定の現在は実施しない。給電許可がONでも駆動入力がないケースで意図しない再許可を起こさないよう、状態と指令を別々に記録する。

## 計測点と時刻

同一時間軸で、STOP入力、EN/許可、左右REGULATOR_OUT、INTERNAL_OUT、SERVO_BUS、最遠サーボ端子電圧、供給/戻り電流、必要に応じDATA線を記録する。VGSはREVERSE_GATE−INTERNAL_OUTを差動測定する。

- t_stop：停止指令の規定端子しきい値を横切った時刻。
- t_isolate：正方向給電が遮断されたことをゲート・電流等で判定できた時刻。判定法と電流分解能は試験前に固定する。
- 放電期限はt_isolate+0.920s。停止応答t_isolate−t_stopも別に保存する。都合のよい電圧下降開始点を後からt_isolateにしない。

t_isolateを実証できなければ放電判定は「未判定」。保護停止時間を放電時間に含めない代わりに、停止指令からの総時間も必ず報告する。

プローブ入力抵抗/容量、差動誤差、オフセット、帯域、標本間隔、時刻同期誤差、電流計の挿入抵抗を記録する。プローブの放電効果を無視して合格にしない。プローブ負荷を補正または最悪側に評価できない場合は未判定。6V・片断線・960µF比較の一定流入余裕は約70.6µAしかなく、微小電流測定の不確かさを含める必要がある。

## 判定

- 電圧上側不確かさと時刻誤差を含め、真の期限でサーボバス/サーボ端子が0.5V以下であることを確認。単一サンプルのしきい値通過だけで判定しない。
- 別途定めた観測期間に再上昇・意図しない再給電がないことを確認。観測期間未設定は未判定。
- 回生や通信流入がある波形へ単一RCの指数近似を当てて「容量」を確定しない。既知負荷E0の容量と、E1の実波形を別に保存する。
- 対照試験の両断線で未放電を観測できない場合、別放電経路/計測負荷を調べる。偶然のサーボ消費で片断線耐性があると結論しない。
- 熱は定常通電時と停止直後の抵抗/周囲温度を測り、完成基板の熱評価に照合。電力が定格未満という算式のみでは合格にしない。

記録の結論は「合格／不合格／未判定／設計不適合で未実施」を区別する。電圧・回生・熱の実測は#49、未完成の保護/通信/実装設計は#21〜#24へ戻す。親Issueの完了条件を変更しない。
