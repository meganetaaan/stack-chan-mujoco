# 旋回・後退候補の正式評価手順

この文書と評価ツールの存在は、正式評価の達成を意味しない。候補の開発検証を終え、ソースを確定してから実行する。現時点の開発比較は `validation/yaw_backward_contact_development_v1/README.md` を参照。

## 固定するもの

`configs/maneuver/acceptance_v1.json` に定めた205秒・24区間の指令と全判定基準を使う。固定条件217000〜217019の20試行、ランダム条件218000〜218019の20試行を実行し、それぞれ20/20、18/20以上の総合通過を求める。運動指標だけでなく、各移動区間の両足の有効着地と、物理サブステップでの転倒・自己衝突・関節制限・保護停止判定を含む。

`yaw_acceptance.py` はモデルの全凍結ファイル、参照軌道、実行エンジン、制御・評価モジュール、ばらつき設定、Pythonと依存パッケージのバージョンを記録する。参照は0〜205秒の20 ms刻み10,251点を必要とする。スナップショット単独では試験を実行しない。

## 実行例

以下の `CHOSEN_REFERENCE` は開発検証を終えた参照ファイルに置き換える。リポジトリルートで実行し、出力先には未使用パスを指定する。

```sh
python yaw_acceptance.py --design assets/r8_yaw_offset_flange_v1 --reference CHOSEN_REFERENCE --out outputs/acceptance_candidate
python run_yaw_acceptance.py --snapshot outputs/acceptance_candidate/snapshot.json --out outputs/acceptance_trials --workers 4
```

実行中は凍結対象を編集しない。開始時と各試行の前後に整合性を検査する。実行器は40試行を固定・ランダムの順に交互に投入し、全試行を記録する。`run_claim.json` によって同じ候補のバッチを誤って再起動することを防ぐ。失敗シードを交換したり、成功するまで再試行したりしない。中断からの自動再開は未実装である。観測のタイムアウト時には元の実行ハンドルを確認し、処理が継続している間は再起動しない。

## 証拠と判定

各試行は状態、着地イベント、プロトコル、実行ソース、パラメータと判定を保存する。実行器は状態から運動指標を再計算し、シードからのパラメータ生成、接地イベントの集計、ハッシュと報告との一致を確認する。物理サブステップの安全判定は凍結した実行エンジンの記録に基づく。記録間隔20 msの軌道だけから1 msの安全判定を再現したとは主張しない。

`summary.json` の成功数、全40試行の一覧、ソース変更の有無を確認する。プロセスエラーと検証エラーも失敗として保存する。合格時にも、実際のMuJoCo状態を `replay_yaw_candidate.py` で動画化し、設計・寸法・物理仮定・公開成果物を目標全体に照らして確認する。集計の合格だけで目標全体を完了扱いにしない。

公開時にはスナップショット、試行状態、動画、全結果、依存環境と再実行手順を揃える。スナップショット中のパスは作成環境に依存するため、別チェックアウトで再実行する場合は同じソース・参照・モデルを確認して新しい出力先にスナップショットを作る。元の正式試験の記録と再現試験を別に保存する。
