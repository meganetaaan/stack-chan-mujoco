# 左右電源監視から停止・再ARMへの接続

## 発見と判断

196部品v4では各SOURCE_WINDOW_ODにTPS3700の出力2端子とプルアップ抵抗しか接続されていなかった。旧監視サブ回路に明記された「未実装シーケンサーへの境界」が統合後も残っていたため、監視ICを載せただけではサーボ停止へ伝わらない。4つの未接続ポート一覧だけでは、この未完箇所を表せていなかった。

v5で両側のOUTA/OUTBを既存RAIL_HEALTH_Nへ接続する。左右いずれかの電圧異常はU7のMRを介してRESET_NをLowにし、既存U6の再ARMラッチをクリア、U3の給電許可を抑止する設計候補。復帰時に自動でラッチを再設定しない既存構成を保持する。MCUやTab5の処理を監視故障の伝達経路に入れない。

[TPS3700 Rev.G §5](https://www.ti.com/lit/ds/symlink/tps3700.pdf)のDDCピン1/6はオープンドレイン出力、[TPS3808 Rev.N §7.3.3](https://www.ti.com/lit/ds/symlink/tps3808.pdf)ではMR LowがRESETをアサートする。これらは接続・極性の根拠であり全電源範囲での動作証明ではない。

## 部品と確認範囲

左右の監視出力プルアップ2個を削除し、既存SYS側R9を使用する。STOP_AUXとSYS電源を追加プルアップで結ばない。196→194部品、旧部品のピン接続変更は左右監視ICの計4端子だけ。監視分圧器と全停止回路を保持。正常電源下の8組の理想論理状態をreport.jsonへ保存した。

再現: `python3 software/sim/circuits/connect_source_window_reset.py`。

## 未完・次の解析の終了条件

統合したノードの漏れ・容量、出力Lowと受信しきい値、TPS3700起動待ち、STOP_AUX喪失、異常検出から実際の遮断までの時間を評価する必要がある。これらの最悪条件の根拠が揃うまで保護合格としない。以前の単独ノード解析は自動流用しない。

レギュレーターALLOWは未接続。これは**SYSのRESET_N／POWER_ENABLE_COMMANDに依存させてはならない**。レギュレーター停止→低電圧検出→RESET継続→レギュレーターを起動できない循環になる。制御側から先に変換器を起動し、電圧が揃ってから既存停止・手動再ARM条件を満たして下流サーボ給電を許可する構成が必要。変換器の起動はサーボの給電許可ではない。
