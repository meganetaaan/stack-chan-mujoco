# タイマー設定異常の全状態での停止保持

修正前コミット516ab5aでは、タイマー未設定・不正値をSTARTUP_EXPIREDへ変換するだけで、実行処理の故障として保持していなかった。RUNでは起動期限を参照しないため、この異常による停止を要求できなかった。

試験前に定めた条件：全6状態で、タイマーなし・期限0・2^31・UINT32_MAXの各条件を与えた場合、その処理でCLEARのみを要求し、状態をCLEAR_RESETに戻して故障を保持する。タイマーを正しい値に戻すだけでは解除しない。
追加検査は修正前に `(phase=0, timer=None, output=2, state=0, fault=0)` で失敗した。修正後は24条件と復旧値入力後の保持検査が通過した。以前の期限境界・桁あふれ・時刻後退・PG同時成立検査も通過した。

再現：

```sh
python3 software/sim/circuits/check_power_deadline.py --out /tmp/power-deadline-v2-check
```

ホスト実行とCortex-M0+向けコンパイルを確認。実際の起動期限、時刻源、独立遮断経路は未確定。CLEAR要求・GPIOラッチ検査は実端子の停止や遮断時間の証明ではない。実装の範囲はEPIC #6の保護シーケンス候補であり、実機試作可の判定には至らない。
