# 監視用電源の起動循環を解消する

前回の負荷側センサーLDO案は「監視が有効になるまで主遮断器を閉じない」という要求と循環する。外部逆給電や回生のない初期状態ではセンサーに給電されず、手動投入を要求しても進めない。依存関係の到達性で確認した。これは電気過渡解析ではない。

## 修正構成

センサー用TPS70933DBVR×2の入力を、逆接等の入力保護より後、主遮断器より前の入力へ移す。入力源が電池でも外部電源でもその電圧範囲を部品仕様と照合する。センサー出力3.3 Vと既存AUX3V3を直接並列にはしない。回生検出用TPS3700とゲートドライバUCC27517は負荷側給電を維持する。

これにより「入力あり→監視電源→監視有効→手動投入→サーボバス」の順序が接続上可能になる。センサーが有効になる時刻、監視回路の故障、バス起動時の過渡、物理遮断能力が証明されたわけではない。

## 制御条件

1. 初期状態は主遮断器オフ。上流監視電源が有効で、センサー・判定器が整定してから手動投入を受け付ける。
2. サーボバス起動中は吸収指令用検出器の状態がまだ有効とは限らない。無効な指令を不一致判定へ用いない。起動過電圧と監視が使えるまでの間は別途ハード回路として検証する。
3. 通常運転中の監視喪失や確定故障は遮断・保持へ進む。停止指令は負荷側吸収回路の給電を切らない。
4. 入力喪失時は能動制御がなくても遮断器がオフへ戻る実装を要求する。入力復帰時の初期状態もオフとし、故障解消・監視有効後の新たな手動操作なしに投入しない。ボタン押しっぱなしを新たな操作にしない。
5. 入力消失中は電流監視も失われ得る。これを有効なゼロ電流として記録しない。負荷側吸収は別給電で継続するが、残留エネルギーと吸収故障の成立評価は未完了。

前回案の失敗は`brake_sensor_supply_review_v1`とこの記録で保持する。現在のカード/BOMは上流入力案を正本とする。入力電源の追加・理想プリチャージ・一時的な監視無視で循環を隠さない。今回の終了条件は依存関係修正まで。#22/#24は未完了。
