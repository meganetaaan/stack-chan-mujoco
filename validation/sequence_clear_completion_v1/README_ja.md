# クリア完了条件の修正

従来の`sequence_clear_handshake_v1`はクリアを要求すると同じ処理内で投入許可をFalseにしていた。これは定常論理の検査であり、実部品がクリアされた証拠ではない。さらに実回路U6にはARMEDとENABLE_PERMISSIONの2つの記憶がある。許可だけのLow観測を完了条件にしたまま実装しない。

新しい契約では、正常な電源状態で、両出力Low・今回の実CLR Low観測・最小クリア保持時間完了をすべて満たすまでクリア要求を保持する。保持の起点はソフトウェア上の指令時刻ではなく、両CLR端子で有効Lowが成立する時点。どちらかの出力が先に変わる観測順序と、両方Lowでも保持時間未達のケースを分離した。32論理条件と4段階の順序確認を保存。

[SN74HCS74 RevD](https://www.ti.com/lit/ds/symlink/sn74hcs74.pdf) §6.7は2／4.5／6 VでCLR Low幅最小11 ns、CLR解除から次CLKまでのsetup最小7／5／5 nsを規定する。伝搬遅延と最小パルス幅は別の規定。これを根拠に「許可出力がLowだから十分な幅だった」と推定しない。実装する保持時間、電源範囲・負荷・配線と全経路遅延は未確定で、11 nsちょうどのパルスを設計値に採用したわけではない。

目的は、クリア回路を作る前に応答を瞬時とする仮定を除き、必要な観測・時間条件を決めること。終了条件は上記の抜けが状態契約からなくなること。実部品の故障を予測する過渡シミュレーションではなく、具体的な遅延値を仮定していない。既存revGの配線は変更せず、状態保持・クリア出力・観測方法の部品設計を#24の残件とする。

```sh
python3 software/sim/circuits/check_sequence_clear_completion.py --out /tmp/sequence-clear-completion
```

出力先は新規。以前の160条件の成功は削除しないが、新しい実装契約や物理タイミングの合格根拠にはしない。
