# 左右電源と再始動の統合状態モデル

以前はCLR完了とタイマーの新旧判定を個別に検査していた。
今回、それらと左右電源の起動・運転条件を実行可能な状態モデルへまとめた。
実回路への配線、GPIO実装、時間保証はなく、#6の完了とは扱わない。

到達可能な6状態（CLEAR内部2状態、WAIT_NEW_PRESS内部2状態、START、RUN）に対し、
独立な10入力の全組合せを適用し、6,144遷移を検査した。
これは入力間に実機上の相関を仮定しない論理検査であり、時間連続系の全故障網羅ではない。

確認した動作：
- 初期状態はCLEAR。外部の両ラッチがLowになる前に解除しない。
- 前回の保持完了Highを流用せず、保持タイマーLowの観測からやり直す。
- CLEAR解除後に許可Lowを観測し、外部の新しい有効な許可でSTARTへ進む。
- STARTでは通常のPG Lowを許容し、両脚PG HighでRUNへ進む。
- タイムアウトとPG成功が同時ならタイムアウトを優先する。
- RUNでどちらかのPGが失われたら給電要求を下げ、CLEARへ進む。
- 電源復帰だけでは再起動しない。

入力ラッチやタイマーをモデル内で勝手にLowへ書き換えない。
例示トレースには片方のラッチだけが残るケースと片脚故障後の復帰も含めた。

## 実回路へ渡す残件

これは理想化したサンプル時点の観測モデルである。
サンプル間の短い故障を記憶する回路、CLRから次のクロックまでの回復時間、
外部許可が新しい物理的な離す／押す操作に対応する保証は未実装。
START時間は変換器・スイッチの起動と故障エネルギーから決める必要があり、
数値を仮置きしてこの論理検査を通していない。

モデルがclear_requestを出したことと、実CLR端子のLow観測は別入力として扱う。
状態回路の実部品・駆動能力・電源遷移を設計してから統合過渡検証へ進める。
EPIC #7以降のロボット制御ファームウェアを実装したものではない。

## 再現

リポジトリルートから未作成の出力先を指定する。

```sh
python3 software/sim/circuits/check_power_sequence_model.py --out /tmp/power-sequence-check
```

plan.jsonは検査条件、report.jsonは到達状態・代表トレース・未確認事項。
同じ条件で再生成した両JSONの一致を確認した。
