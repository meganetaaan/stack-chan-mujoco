# Tab5メーカーSTLの背面照合

## 設計判断

簡略CADの平坦な背面を蓋の前方ストッパーとして使う判定は、実形状に継承しない。
メーカーSTLには蓋位置付近の凹部・開口があり、次案はTab5背面だけに蓋保持を依存させない構成とする。
今回の点サンプルだけで蓋全体が抜けるとも断定しない。

## データと処理

[メーカー構造データ](https://github.com/m5stack/M5_Hardware/tree/master/Products/C145_Tab5/Structures)のTab5.stlを取得。
全体には10連結成分があり、5部品の組立配置と、それらをY負方向へ移した分解配置を含む。
そのまま全体外接寸法をTab5寸法として扱わない。Y正側5成分を選び、128×80×12mmの組立範囲を確認した。
座標変換と全成分の範囲、ファイルSHA256はreport.jsonに記録。

蓋前端X51.8mmから+X方向へ、各蓋の端面を3×3点、計36点照射して最初の三角形交点を計算。
点ごとの前方距離は約0.3〜6.2mm。一部は交点なし。簡略CADの一様な0.2mm隙間とは一致しない。
面積全体・公差・弾性変形の検査ではない。変換は外接寸法と現行向きに合わせた公称配置であり、全穴の位置保証ではない。

当初trimeshのレイ機能はrtree未導入で失敗。追加インストールに依存せず、YZ投影の三角形重心座標で
+Xの交点を計算する実装へ切り替えた。平行三角形は除外。最初の試行の無効演算警告もマスク処理で解消した。
36点のサンプル数を増やすだけの反復は行わず、保持構造の依存関係を修正する。

## 再現

メーカーURLからSTLを取得後、`.venv-engineering/bin/python software/sim/structural/check_tab5_vendor_back.py /path/to/Tab5.stl`。
SHA256が記録と異なるファイルは停止する。メーカー更新版は別途形状差を確認する。
メーカーSTLは今回リポジトリへ再配布せず、取得URLとハッシュを保存。
製作HOLD。過去の6軸拘束確認は「簡略Tab5形状に限る」という範囲の記録として保持する。
