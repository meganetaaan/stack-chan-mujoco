# BQホストのウォッチドッグと禁止保持候補

**製作HOLD。** 電池保護100部品、統合223部品。CPUの許可出力を直接使う接続を変更し、
外付け監視と禁止保持を経由させた。回路全体の安全性・停止時間の合格ではない。

## 設計判断と一次資料

- [TPS3431 Rev.A](https://www.ti.com/lit/ds/symlink/tps3431.pdf)：SET1/ENを電源へ固定し、CPUから無効化できない構成。CWDへ10kΩを接続する短い固定設定を候補にした。時間切れ出力はラッチではなくパルス。
- [SN74LVC1G74 Rev.G](https://www.ti.com/lit/ds/symlink/sn74lvc1g74.pdf)：異常で非同期クリアし、その後の解除だけでは許可が戻らない記憶を追加。Qは5番、反転Qは3番。
- [SN74LVC1G08 Rev.AA](https://www.ti.com/lit/ds/symlink/sn74lvc1g08.pdf)：CPU要求と記憶された許可のANDを主給電・補助給電それぞれへ接続。
- [74LVC1G17](https://assets.nexperia.com/documents/data-sheet/74LVC1G17.pdf)：容量のあるNRSTをラッチ入力へ渡す前にシュミット入力で受ける。受信電圧と応答の最終適合は未確認。

200ms公称（170〜230ms）は部品が用意する短い固定設定を検討するための候補であり、
ユーザー要求や機械・電源の許容停止時間から導いた合格基準ではない。
短絡やセル低電圧はBQ等の自律保護が担当し、このCPU監視で置換しない。
CPUが動作を続ける予備充電停滞には反応しないため、予備充電そのものの中止期限も別途必要。

## 接続の変更

CPU PA0→BQ_MAIN_REQUEST_RAW、PA1→BQ_AUX_REQUEST_RAW、PA3→BQ_ARM_EDGE。
従来のBQ_ALLOW_BMINUSとBQ_AUX_START_REQUESTはANDゲートの出力に変更。
WDIはPA12のBQ_HOST_HEARTBEAT。WDOは電圧監視出力とNRSTに接続。
禁止記憶ラッチのD/PREはHigh、CLRはNRSTを受けたシュミット出力。
各ICの100nFと、初期状態をLowにする要求・ARMプルダウンを追加。
詳細の正本はbq_host_watchdog_candidate.json。既存GPIO初期化コードはこの変更に未対応。

## 事前に定めた機能評価

1. 要求とARMがHighで停止しても、ウォッチドッグ異常後は出力Low。
2. 異常パルスが終了しても禁止を保持。
3. リセット中のARM立上りは、リセット解除後の許可として予約されない。
4. 正常時の主／補助要求は独立し、電圧低下後は再許可が必要。

上記を4シナリオの理想論理モデルで確認した。単純に異常出力と要求をANDする比較回路では、
パルス終了で再許可してしまう反例も同じ記録に残した。
新しいARMエッジなら再許可できることも記録している。したがって、これは誤ったソフトが
自動でARMを再発行することまで防ぐ回路ではない。

## 未確認事項と終了条件

- 再起動時に自動ARMしない制御と、異常後の新しいユーザー許可を受ける経路は未実装。
- WDOのLow仕様の試験電圧は5V。実使用3.0〜3.6Vでの受信適合を保証したとは扱わない。
- NRSTには100nFがあり、出力の時間仕様をそのまま適用できない。プルアップ・漏れ・入力負荷も更新が必要。
- ラッチの初期化、復帰時のタイミング条件、部分給電、出力固着、ゲート／ラッチ自体の故障は未検証。
- 自由走行タイマーやDMAからのハートビートは禁止する設計方針。アプリの処理完了に基づく更新はまだ実装されていない。
- BQ設定前はBOTHOFFが無効。今回のゲートだけで電池接続直後の保護成立とはしない。
- AUXの接地境界ドライバーは未実装。サーボとTab5が実際に停止する時間は未証明。

次はレベル・漏れ・NRST負荷を含む接続適合と、異常後の復帰経路を確定する。
停止遅延の上限と被保護回路の許容時間を比較できるまでは、安全期限を230msに決めない。
理想モデルのシナリオ追加だけではこれらを解消できないため、このモデルの拡張はここで止める。

```sh
.venv-engineering/bin/python software/sim/circuits/check_bq_watchdog_latch.py \
  --out validation/bq_watchdog_latch_v1
```
