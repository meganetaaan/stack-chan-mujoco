# デバウンス待ち押下による誤再許可

前回の単一DFF接続案を、デバウンスの状態を含めて確認したところ反例が成立した。

- 0 ms：故障中、ボタン解除、DFFクリア。
- 10 ms：故障中に押下し、そのまま保持。
- 20 ms：故障解消、CLR解除。デバウンス出力はまだ解除状態。
- 60 ms：50 msのデバウンス後に押下エッジが到着。D=HighのDFFがセット。

50 msは選定候補の20〜80 ms範囲内の反例条件。実部品の過渡再現ではないが、この許容動作を排除できない接続案を承認できない。故障解消後に物理的な解除・新押下はない。接点バウンスがなくても発生する。

## 設計判断

**SN74HCS74片側をD=Highとして、デバウンス出力反転を直接CLKへ入れる案は現状不合格。** 部品候補自体を否定するものではない。`manual_rearm_logic_v1`は有効な整形済み操作を前提とする抽象仕様として残すが、この回路との等価性は失敗とする。

実装には、故障/電源不正で消去され、健全になってからボタンの安定解除を確認して初めて成立する「再許可受付」状態が必要。その状態が成立する前に届いた押下は記憶しない。故障解消直後のデバウンス出力Highだけを解除確認に使うと、同じ遅延が残る。内部に保留された操作がないことを含めた解除資格付けを回路化する。

停止や故障のクリア経路は非同期優先のまま維持し、故障信号をデバウンス時間だけ遅らせて解決しない。解除資格付けの時間と実部品、入力状態、リセット順序、CLK/CLR競合を定めた後に今回の反例を再評価する。未設計の段を理想ゲートで埋めて完成扱いにしない。
