# revD単体の自動再投入反例

結論：独立クランプを追加したrevDだけでは、新操作なしの再投入を防げない。前回の静的Low成立は取り消さないが、それを復帰動作の合格へ拡張しない。POWER_ENABLE_COMMANDを単に保持信号で駆動する構成を不採用とする。

## 条件と結果

TPS3808G33の既存公差±1.5%から、U7の下降しきい値3.02395 V、U9を3.11605 Vとする。3.3 Vから3.07 Vへ十分長く低下すると、U9だけがENを止め、U7はRESET_Nを解除しない。ラッチ許可とPOWER_ENABLE_COMMANDが保持されているなら、3.3 Vへ復帰してU9の解除待ちが終わると、新しい押下なしでENがHighになる。

動的な未規定出力を仮定せず、各段の遷移が落ち着いた状態で成立する反例である。電源・しきい値は既存候補の仕様と許容条件内であり、部品が同じ型式だから同時に作動するとは扱わない。ソース仕様はschematics/power/manual_rearm_supervisor_candidate.json、接続根拠はmanual_rearm_revD/assembly.json（SHA256をplan.jsonに保存）。

## 設計への反映

- 起動・停止監視は、給電停止を保持し、許可を取り消す必要がある。復帰は既存の安定解除後の新押下条件を通す。
- 既存のPG監視方針はこの機能を提供し得るが、実回路の応答時間・パルス捕捉が未検証。PGによる停止が間に合うと仮定して、この反例を解決済みにしない。
- MAIN_EFUSE_ENとRESET_Nを直結する修正は、正常なEN Lowでもラッチをクリアし起動を阻むので採用しない。クランプ原因を独立した信号として取り出すか、給電成立の喪失を確実に記憶する回路が必要。
- しきい値差をゼロにしたり、クランプ解除時間を延ばすだけで合格にはしない。保持された許可を取り消さなければ、遅れて再投入するだけである。

未実装の完成シーケンサ全体が不可能であるという結論ではない。現revDに存在しない機能を明確にした。#24は未完了、通電試作保留。

再現：`python3 software/sim/circuits/check_dual_supervisor_recovery.py --out /tmp/dual_supervisor_recovery`。未作成出力先を指定。反例を正しく検出すればスクリプトは正常終了し、report.json内のrevD_alone_no_auto_restartはFAILとなる。正常終了を回路合格と混同しない。
