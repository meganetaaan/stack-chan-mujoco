# 監視ICの起動待ちを追加した比較回路

**通電試作へ進めない。** revFへ専用TPS3808G33、100 kΩ、100 nFを追加した
90部品・297端子。再始動時のCLR保持タイマーとは別の回路である。

## 判断と根拠

ユーザー要求は給電・保護の成立確認であり、12 msという時間指定はない。
今回の設計上の要求は、起動中の監視出力を正常判定として受け入れないこと。
TPS3700は電源1.8 V超過後、起動に最大450 µs必要。
TPS3808G33のSENSE・VDD・MRを同じSTOP_AUX3V3へ接続し、CTを開放する。
その出力は未実装の状態回路へ渡すインターフェースとして残し、ENへ直結しない。

メーカー規定からの条件付き比較：
- 遅延下限12 ms、監視起動上限との差11.55 ms。
- 負方向閾値上限とヒステリシス上限を保守的に組み合わせ、復帰閾値上限3.193951 V。
- 既存LDOの条件付き下限3.207 Vとの差13.049 mV。電源ノイズ込みの保証ではない。

適用条件は、両IC端子が共通電源で、単調に立ち上がり、その後有効電圧を維持すること。
出力負荷100 kΩ・50 pFなどのデータシート条件も必要で、受信回路・基板寄生を含む適合は未確認。
この計算を過渡シミュレーションや電源保護全体の合格とは呼ばない。

## この追加で解消しないことと終了条件

短い電源低下で監視ICだけが無効になり、タイマーが再始動しない可能性を除外できない。
SENSE入力パルスの規定は20 µs、かつ指定振幅条件付きであり、任意の短い低下の検出保証ではない。
POR以下の出力も正常信号として扱えない。

次の設計評価は、受信ICの部分給電時動作と入力負荷を含め、
電源無効→給電禁止→監視再起動待ち→新しい手動操作、という実回路の経路を閉じること。
終了条件は、適用する電源遷移の範囲と、各遷移での禁止・再判定の最悪時間が部品仕様から示せること。
電圧低下の最短時間を都合よく仮置きして合格にしない。
未実装の状態回路は#6の設計残件として残し、実測Issueへ移して完了扱いにしない。

## 再現

リポジトリのルートから、未作成の出力先を指定する。

```sh
python3 software/sim/circuits/add_monitor_startup_timer.py --out /tmp/monitor-start-check
```

出力のassembly.jsonとintegration_report.jsonを本ディレクトリと比較する。
接続検査と条件付き数値比較であり、IC内部の過渡モデルは使用しない。
