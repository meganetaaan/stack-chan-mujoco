# 電池保護と左右サーボ電源の統合接続候補

## 結論

**製作HOLD。** 226部品の接続候補を初めて同一ネット名体系に統合した。
Tab5分岐・予備充電回路・主ヒューズ等は未実装。BQローカルホストの接続は追加したが、監視・境界回路とソフトは未実装であり、全機電源の完成図ではない。
部品表には未選定10参照も含む。接続検査の成功を回路動作・異常保護の合格には扱わない。
#21〜#24は未完了。設計未完了を実測Issueへ移管して完了扱いにはしない。

## 今回の設計判断

ユーザー要求はTab5と12軸への適合、通常・最悪・異常時の保護成立である。
以下の接続はそのための**設計候補**であり、ユーザーが指定した方式ではない。

| 元のシステム側ネット | 統合接続 | 理由・影響 |
|---|---|---|
| BATTERY_RAW | PACK_POS_PROTECTED | 停止・制御電源も主FET後段へ。セル低電圧遮断を迂回する常時負荷にしない |
| DRIVE_BATTERY_PROTECTED | PACK_POS_PROTECTED | 左右レギュレーターを同じ保護後電源へ |
| GND | PACK_RETURN | システム負荷の戻り電流をシャント経由にする |

BQの設定用電源BQ_CTRL3V3とそのローカルホストはCELL_B_MINUS基準に残す。
SYS側LOGIC3V3と同一ネットにはしない。信号配線のために両GNDを直結するとシャントを迂回する。
これは絶縁要求を確定するものではない。接地差、論理しきい値、無給電時の注入電流を満たす
境界回路が必要で、その方式・部品は未選定。デバッグ器やUSBによる意図しない接地も評価対象。

この接続では主FET遮断で停止回路の補助電源も失われる。制御電源が残ることを前提にした
停止処理は使用できない。局所プルダウンや放電抵抗は候補として存在するが、電源消失中の
FETゲート、残留電圧、回生、再起動禁止の成立は別途確認する必要がある。

## 起動順序の設計条件（未実装）

| 段階 | 必要な状態 | 現状の不足 |

| 電池接続 | BQローカル電源を起動、主負荷の許可を保持しない | 主保護・設定前のFET状態・起動余裕の未検証 |
| 設定確認 | セル対応、保護値、CRC、BOTHOFF機能と状態を確認 | ローカルホスト接続済み、設定処理・監視回路が未実装 |
| 予備充電 | 左右ENAはLow、サーボeFuseはOFF、Tab5はOFF | PDSG外部回路、Tab5禁止、独立中止回路が未実装 |
| 主給電への移行 | 電圧差条件を満たす。時間切れによるDSG ONは禁止する候補 | 測定誤差、残留突入電流、終了判定が未検証 |
| ロボット起動 | 電源と監視値が有効になった後、明示的な許可で起動 | シーケンサー、ENAドライバー、復帰条件が未実装 |
| 故障・リセット | 主負荷の許可を解除し自動再始動しない | 部分給電・CPU停止を含む独立経路が未検証 |

初版の制約：予備充電中もSYSの制御・停止電源が自動起動する接続だった。
現在は制御電源分岐にSHDNプルダウンを追加した。停止電源はまだ自動起動する。
その消費電流と入力容量をゼロとしてPDSGを選定できない。
先の100Ω・終了差0.5Vは説明用の仮置きで、到達には定常負荷が5mA未満という条件が付く。
今回の統合回路がこの条件を満たす証拠はない。これらの数値を実装値には採用していない。
まず実装予定の補助負荷・起動電流を集計し、必要なら補助負荷の起動禁止または予備充電方式を
変更する。未知容量のRCスイープ追加だけではこの判断は解決しない。

## 再現と評価範囲

リポジトリ直下から：

```sh
.venv-engineering/bin/python software/sim/circuits/integrate_system_power.py \
  --out schematics/power/system_power_integration_candidate_v1
```

`assembly.json`は元の部品情報を保持し、接続の正本は`parts[].pins`と`interconnects`とする。
入れ子の部品仕様メモには元のローカルネット名が残る。各部品には元ファイルと参照名を付記。
`BAT__` / `SYS__`で参照を分離し、明示した3接続以外はネット名一致による自動接続をしない。
元ファイルのSHA256を結果に記録する。元回路の未検証条件は引き続き適用される。

検査は明示銅箔によるシャント・主FET・左右出力の短絡がないことと、指定した給電・帰還接続。
半導体内部の導通、漏れ、基板接地、過渡・温度・単一故障を証明する検査ではない。
`report.json`の未選定一覧はpart未記入だけを抽出するため、型番のある部品の適合性や
基板上に未追加の部品まで網羅した完了判定には使わない。

## 次の設計の終了条件

1. 予備充電中の全負荷をこの統合接続から列挙し、上限の根拠を持てるか判断する。
   上限未確定なら採用不可として回路構成を再選択し、仮定を増やして合格にしない。
2. Tab5分岐とローカルホストの実部品・禁止経路を統合し、未接続電源と接地境界を解消する。
3. PDSGと主保護を選定し、短絡持続時の損失・遮断・失敗時状態まで机上で成立させる。
   その後に全機の通常・起動・停止・故障のシミュレーションへ進む。

実測へ渡すのは選定済み部品の熱・実負荷・寄生・足裏摩擦等である。
未設計の電源枝や禁止回路は#21〜#24側に残す。機構の強度・干渉判定をこの接続検査で代替しない。

## 制御電源の起動禁止を追加

SYS__U_LOGIC_PROTECTの14番SHDNを開放から10kΩプルダウンへ変更し、
外部許可SYS__LOGIC_START_ALLOWから1kΩ直列で駆動する候補にした。
SHDNの基準はGND＝PACK_RETURN。UVLO/OVP用RTNと混同しない。
部品候補はTNPW060310K0BEEA / TNPW06031K00BEEA。

制御電源の20mAはユーザー要求でも実測値でもなく既存の設計予算。
この負荷を許容するまま100Ω・終了差0.5Vを採用できないため、負荷を起動後へ分離する。
20mAを小さく書き換えて通すことはしない。予備充電抵抗の値は依然未選定。

静的検算では総抵抗変動±1%の仮置きで、0.4V時の吸込み能力39.60µAは
メーカーの10µA条件を超える。3.0V駆動時の抵抗分圧は最低2.722V。
これは温度・3S入力・起動過渡・無給電時・ドライバー適合を含む保証ではない。
SHDNをLowにしても入力側自己消費、分圧・放電抵抗、STOP系統、Pololu入力負荷は残る。
全体予備充電負荷の上限はまだ未確定。

SYS__LOGIC3V3で動くシーケンサーを許可ドライバーにすると、自分の電源を起動できない。
先に起動するBQ側から接地差を考慮した許可を渡す回路が必要で、まだ実装されていない。
この未接続をジャンパーHighで迂回した製作は許可していない。

一次資料：[TI TPS2660x Rev.G](https://www.ti.com/lit/ds/symlink/tps2660.pdf)、
7.5および9.3.5.7。24V条件の自己消費値を3Sでの保証値には転用しない。
検算結果はvalidation/logic_predischarge_inhibit_v1/report.json。

```sh
.venv-engineering/bin/python software/sim/circuits/screen_logic_predischarge_inhibit.py \
  --out validation/logic_predischarge_inhibit_v1
```

## ホスト電源監視の追加

TPS3808G01と分圧・バイパスを追加。NRST外付けプルアップを100kΩに修正。
静的検算と未確認事項はvalidation/bq_host_supervisor_v1/README_ja.md。
急な電源低下への応答と独立停止は未合格。

## CPU停止に対する禁止保持

BQ側にTPS3431とラッチ/AND回路を追加。理想論理の結果と残課題は
validation/bq_watchdog_latch_v1/README_ja.md。異常パルス終了による再許可は防ぐ構成だが、
再ARMのユーザー許可経路、電気的適合、停止時間は未合格。

## 起動許可の接地境界接続

ISO7710FDRをBQ_AUX_START_REQUESTからSYS__LOGIC_START_ALLOWへ追加。
出力側給電はSTOP_AUX3V3で、まだOFFのLOGIC3V3に依存しない。
追加負荷を含む静的比較はvalidation/aux_start_isolator_v1/README_ja.md。
過渡・起動・部分給電と全電源余裕は未合格。
