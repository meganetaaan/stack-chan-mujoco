# 電源シーケンスのCコア

#6の電源状態制御用ライブラリ。ロボットの歩行・通信を扱うEPIC #7以降の
制御ファームウェアではない。ボードへ書き込める完成ファームウェアでもない。

初期状態はPOWER_CLEAR_RESET。入力は独立に確認された観測値をビットで渡す。
`power_sequence_outputs`は現在状態と観測から出力要求を返し、
`power_sequence_next`は次状態を返す。どちらもGPIOや外部ラッチを書き換えない。
入力と出力のビット割当はヘッダに定義した。

実装前提：
- CLR Lowは実際の2端子を確認した値。clear指令のコピーを渡さない。
- source/PG/healthは未資格の生信号ではなく、電源有効性を含む観測を渡す。
- タイマーは開始・解除と完了観測の関係を実装し、過去の完了を使い回さない。
- 出力要求の更新順序、非同期故障記憶、リセット回復時間はボード側で保証する。
- モデル上の即時抑止はポーリング周期内の短い故障を捕捉する保証ではない。

状態番号や入力の未定義ビットが不正なら、給電要求を出さずクリアを要求する。
この処理はCPU停止やメモリ全体の破損への保護を保証しない。

## 検証

参照Pythonモデルと6状態×1024入力で出力と次状態を比較し、全件一致。
不正符号の代表536ケースも確認した。ホストとCortex-M0+向けのコンパイルを通した。
Armのオブジェクト生成は起動・リンク・実機動作の検証ではない。

```sh
python3 software/sim/circuits/check_power_sequence_c.py --out /tmp/power-sequence-c
```

コンパイラ版・入力ハッシュ・残件はvalidation/power_sequence_c_v1/report.json。
GPIO初期化のレジスタ操作コアはg030_gpio_init.cへ追加。実MMIOアダプター、クロック、ウォッチドッグ、起動コード、回路統合は未実装。

GPIO初期化は出力ラッチを読み戻してから出力化する。失敗時の順序検査はvalidation/g030_gpio_latch_failure_v1とg030_gpio_init_v2を参照。

出力要求のレジスタ反映はg030_gpio_outputs.c。3端子を単一BSRRで更新するが、物理端子の観測・遅延保証ではない。書込み失敗を記憶する呼出し側はpower_runtime.cへ追加。実MMIO接続は未実装。

power_runtime_bootは起動時専用。実CLR解除後の許可Low観測を要求し、IO故障は再起動まで解除しない。検査はvalidation/power_runtime_v1参照。

起動期限はpower_deadline.cで実行処理へ接続した。既定の実時間値はなく、無効設定では起動しない。実時刻源・周波数誤差・期限選定・時計停止時の監視は未完了。
